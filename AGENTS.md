# Выполнение тестовой задачи

Эти инструкции действуют, когда пользователь просит выполнить заложенную здесь
тестовую задачу. При разработке самого стенда следуйте заданию его владельца;
незавершённое приложение в `stockctl/` — намеренный исходный материал.

## Обычный запуск по ссылке

1. Используйте новый clone этого репозитория для каждой попытки. Не переносите
   решения, отчёты или историю диалога от предыдущей попытки.
   В `CASE.json` указан текущий сценарий; по умолчанию это `workflow`.
   Если пользователь назвал другой сценарий, сначала подготовьте его командой
   `python3 bench.py prepare --case <small|workflow|parallel|handoff> --output <новый-каталог>`
   и выполняйте задачу в созданном каталоге. Список сценариев: `python3 bench.py cases`.
2. До чтения реализации и изменения файлов выполните `python3 bench.py start`.
   Если пользователь указал вариант, модель или точный commit Toolkit, передайте
   их через `--label`, `--model`, `--effort`, `--toolkit-ref`. Не угадывайте значения.
   Без этих данных функциональный результат полезен, но строгое сравнение
   конфигураций невозможно.
3. Прочитайте `TASK.md` и `docs/contracts.md`, выполните задачу. Используйте
   уже доступные правила и навыки своей среды. Стенд не назначает число
   субагентов и не требует отдельного вызова навыков.
4. Разрешены изменения пакета текущего сценария: `stockctl/**` для `workflow`,
   `statusctl/**` для `small`, `opsreport/**` для `parallel`, `shelfctl/**` для
   `handoff`; также новые тесты в `tests_solution/**` и
   необязательный `docs/solution.md`. Можно запускать существующие проверки
   и писать тесты решения. Не меняйте `TASK.md`, условия приёмки, `tests_product/`,
   `verification/`, `benchmark/`, `bench.py`, `CASE.json`, инструкции, исходные контракты
   или данные измерений. Не устанавливайте зависимости: достаточно Python 3.11+.
   Для временных внутренних заданий, отчётов ревью и передачи результатов между
   агентами разрешён `.codex/tmp/`; он не входит в patch решения.
5. После завершения своей работы и предусмотренного вашей средой ревью выполните
   `python3 bench.py finish` ровно один раз. Ненулевой код означает, что попытка
   зафиксирована с ошибками; сохраните её результат. Следующая попытка начинается
   в новом clone. Для промежуточной проверки можно запускать
   `python3 -I verification/check.py --workspace .` для `workflow`;
   для остальных — `verification/small_case.py`, `parallel_case.py`, `handoff_case.py`.
6. Верните пользователю три файла из выведенного каталога:
   **`REPORT.md`, `report.json`, `changes.patch`**. В ответе достаточно результата,
   времени, числа пройденных критериев и ссылок на файлы. Не переписывайте отчёт
   вручную и не объявляйте экономию без сравнения повторных запусков.

Коммиты, push и PR для решения тестовой задачи не нужны, если пользователь
не попросил их отдельно. Сама задача полностью находится в этом репозитории.

## Сценарий handoff

В первой сессии выполните только первый этап из `TASK.md`: сохраните план
в `.codex/tmp/plan.md`, затем выполните `python3 bench.py checkpoint` и остановитесь.
Передайте выведенное уточнение новой сессии в том же рабочем каталоге. Во второй
сессии используйте сохранённый план и последнее уточнение; заново `start` не
запускайте. После реализации выполните `finish`. Не читайте
`.benchmark/next-phase.md` до фиксации первого этапа.

Параметр `start --subagents N` только записывает уже действующее ограничение.
Для управляемого эксперимента ограничение устанавливает внешний `run`/`matrix`;
не заявляйте, что число потоков изменено обычным `start`.

## Если попытку запустил внешний контроллер

Если `.benchmark/current.json` уже содержит `"mode": "external"`, измерение
началось. Не запускайте `start` или `finish`, не изменяйте этот файл. Выполните
задачу и верните краткий итог; контроллер сам запустит приёмку и создаст отчёт
после завершения агента. Не запускайте вложенный `bench.py run`.
Для `handoff` внешний контроллер также сам фиксирует план и запускает вторую
сессию. Не вызывайте `checkpoint` из агента в этом режиме.
