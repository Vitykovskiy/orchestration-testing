# Тестовая задача: подготовить складской CLI к повторным запросам

`stockctl` — небольшой инструмент учёта товара по складам. В нём уже работают
добавление товара, резервирование, отмена и отгрузка. Для выпуска нужно исправить
два дефекта, добавить безопасное повторение запроса и закончить экспорт.

## Что сделать

1. Исправить отмену резерва. Повторная отмена сейчас повторно освобождает товар.
   Она должна возвращать прежний результат без повторного изменения остатков
   и журнала. Другие резервы этой позиции должны остаться действующими.
2. Исправить выборку остатков. Команда для одного склада показывает позиции
   других складов. JSON и текстовый вывод должны содержать только запрошенный
   склад; неизвестный склад возвращает пустой результат.
3. Реализовать зарегистрированные экспортёры: остатки в JSON и движения в CSV.
   Соблюсти поля, порядок строк, пустые результаты и экранирование из
   [контрактов](docs/contracts.md). Экспорт не изменяет данные.
4. Добавить необязательный `--request-id` к резервированию. Повтор одинакового
   запроса с ключом возвращает тот же резерв. Повтор ключа с другими параметрами
   завершается ошибкой без изменений. Ключ переживает перезапуск процесса.
   Старые базы и вызовы без ключа должны сохранить работоспособность.

Полные правила, примеры JSON, старая схема базы и поведение ошибок закреплены
в [docs/contracts.md](docs/contracts.md). Это критерии приёмки.

## Область работы

Изменять реализацию в `stockctl/`; при необходимости добавлять новые проверки
в `tests_solution/` и описание решения в `docs/solution.md`. Сохранить исходные
проверки `tests_product/`, это задание, контракты, инструкции и средства измерения
стенда. Дополнительные зависимости не нужны. Не добавлять интерфейс пользователя,
сетевые сервисы или параллельную обработку. Отдельные роли и количество агентов
не предписаны.

Начать с инструкции запуска в `AGENTS.md`: она фиксирует начало измерения.
После доработки выполнить проверки и сформировать короткий отчёт предусмотренной
там командой. Все попытки исправления и проверки входят в один запуск.

## Существующая проверка

```sh
python3 -m unittest discover -s tests_product -v
```

Эти проверки сохраняют уже работающие операции и проходят до выполнения задачи.
Сам факт их успешного выполнения не подтверждает новые требования.

## Пример обычной работы

```sh
python3 -m stockctl --db /tmp/stockctl-example.sqlite init
python3 -m stockctl --db /tmp/stockctl-example.sqlite stock add --warehouse W1 --sku SKU-A --qty 10
python3 -m stockctl --db /tmp/stockctl-example.sqlite reserve --warehouse W1 --sku SKU-A --qty 2
python3 -m stockctl --db /tmp/stockctl-example.sqlite cancel 1
python3 -m stockctl --db /tmp/stockctl-example.sqlite stock list --warehouse W1 --format json
```

В новой пустой базе последнее действие возвращает позицию с `on_hand = 10`,
`reserved = 0`, `available = 10`. Повтор `cancel 1` должен сохранить эти числа.
