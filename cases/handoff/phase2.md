# Handoff: продолжить с уточнёнными требованиями

Продолжите работу по сохранённому плану `.codex/tmp/plan.md` и реализуйте CSV.

Уточнение: итоговый отчёт обязан содержать столбцы
`warehouse,sku,on_hand,reserved,available` именно в таком порядке.
Сортировка — сначала по `warehouse`, затем по `sku`, в обычном порядке строк
Python. Эти требования заменяют прежние три столбца и сортировку только по SKU.

Добавьте `--format csv` к существующей команде:

```sh
python3 -m shelfctl --input snapshot.json report --format csv
python3 -m shelfctl --input snapshot.json report --format csv --warehouse W2
```

Правила приёмки:

- CSV использует запятую, обычное CSV-экранирование кавычек, запятых и переносов
  строк, UTF-8 и перевод строки LF. Пустой результат содержит только заголовок.
- Дубликаты пары `(warehouse, sku)` объединяются по существующим правилам
  приложения: суммируются `on_hand` и `reserved`, `available` вычисляется после
  объединения. Это правило действует до фильтрации и сортировки результата.
- Фильтр склада и неизвестный склад работают как для существующих форматов.
- JSON и текстовый вывод, их порядок строк, форматирование, валидация и коды
  ошибок должны сохранить прежнее поведение. Входной файл не изменяется.

Изменять можно `shelfctl/**`, добавлять тесты в `tests_solution/**` и при
необходимости описание решения в `docs/solution.md`. Сохраните исходные
контракты, тесты `tests_product/`, инструкции и проверяющие программы.
Дополнительные зависимости не нужны. Количество агентов и распределение
работы не предписаны.

Выполните необходимые проверки и верните краткий результат. Завершите измерение
по `AGENTS.md`: в ручной попытке выполните `python3 bench.py finish`; если попытку
запустил внешний контроллер, оставьте формирование отчёта ему. Повторно
`bench.py start` не запускайте.
