# Существующий контракт shelfctl

## Вход

Входной файл — один JSON-объект:

```json
{"snapshot":"morning","items":[{"warehouse":"W2","sku":"A","on_hand":10,"reserved":3}]}
```

`snapshot` — непустая строка; `items` — массив объектов. `warehouse` и `sku` —
непустые строки. `on_hand` и `reserved` — неотрицательные целые числа; значения
bool не считаются целыми. `reserved` не может превышать `on_hand`.
Нарушение этих правил — ошибка предметной области.

Позиции с одинаковой парой `(warehouse, sku)` объединяются: обе числовые
величины суммируются, `available = on_hand - reserved`. Для существующих
форматов сохраняется порядок первого появления пары во входе.
Фильтр `--warehouse` применяется к объединённым строкам. Неизвестный склад
возвращает пустой отчёт, а не ошибку.

## JSON

```sh
python3 -m shelfctl --input snapshot.json report --format json
```

Результат состоит из `snapshot`, `rows` и `totals` в таком порядке.
Строки содержат `warehouse, sku, on_hand, reserved, available` в таком порядке.
`totals` содержит суммы `on_hand, reserved, available` для отфильтрованных строк.

Выводится один JSON-объект, `ensure_ascii=False`, без пробелов вокруг разделителей
и с одним LF в конце. Пример:

```json
{"snapshot":"morning","rows":[{"warehouse":"W2","sku":"A","on_hand":10,"reserved":3,"available":7}],"totals":{"on_hand":10,"reserved":3,"available":7}}
```

## Текст

```sh
python3 -m shelfctl --input snapshot.json report --format text
```

Первая строка — `Склад<TAB>SKU<TAB>В наличии<TAB>Резерв<TAB>Доступно`.
Далее следуют строки данных в том же порядке, что и JSON, разделённые TAB.
Все строки завершаются LF. Для пустого результата выводится только заголовок.
Это простой диагностический формат; задача не требует менять его экранирование.

## Ошибки и побочные эффекты

Успех: код 0, результат в stdout, пустой stderr.
Ошибка предметной области: код 2, пустой stdout, JSON-объект с непустой строкой
`error` в stderr. Ошибки разбора CLI сохраняют стандартное поведение argparse.
Никакая команда не изменяет входной файл.

## Новые форматы

Столбцы и порядок CSV определяются текущим этапом пользовательского задания.
Общие правила CSV: разделитель запятая; кавычки, запятые и переводы строк
экранируются по стандартным правилам CSV; кодировка UTF-8; разделитель записей LF;
нулевое число строк данных всё равно даёт заголовок.
