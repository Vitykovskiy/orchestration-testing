# Параллельная задача: выпустить набор эксплуатационных отчётов

Команда эксплуатации получает JSON-файлы событий сервисов. CLI `opsreport`
уже читает и проверяет данные, поддерживает выбор отчёта и содержит реестр
шести отчётов. Их реализация ещё не завершена.

Реализуй все шесть отчётов по [контрактам](docs/contracts.md):

| Отчёт | Результат |
|---|---|
| `latency` | Распределение задержек успешных запросов по сервисам |
| `reliability` | Доступность и наибольшая серия ошибок |
| `throughput` | Запросы и объём данных в минутных окнах UTC |
| `incidents` | Непрерывные интервалы ошибок и восстановление |
| `traffic` | Нагрузка по путям запросов без query/fragment |
| `audit` | CSV-журнал событий с корректным экранированием |

Все отчёты должны работать отдельно и через уже зарегистрированный `report all`.
Сохрани проверку входных данных, команды `reports` и `check`, коды возврата,
детерминированный порядок результатов и отсутствие записи во входной файл.
Предусмотри пустые данные, ошибки без успешных событий, одинаковое время,
разные часовые пояса, граничные значения и текст со специальными символами.

Это одна поставка из нескольких частей с общим интерфейсом. Выбери способ
разделения работы самостоятельно в пределах доступных возможностей. Количество
агентов, порядок реализации модулей и внутреннее устройство решения не заданы.

Разрешены изменения `opsreport/**`, новые тесты `tests_solution/**` и
необязательный `docs/solution.md`. Не изменяй задание, контракты, исходные
проверки и средства измерения. Новые зависимости и сетевые сервисы не нужны.
Начало и завершение попытки фиксируются согласно `AGENTS.md`.

Примеры команд:

```sh
python3 -m opsreport reports
python3 -m opsreport --input events.json check
python3 -m opsreport --input events.json report latency
python3 -m opsreport --input events.json report all
```
