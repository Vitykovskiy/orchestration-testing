# Контракты opsreport

## Вход и общие правила

Входной UTF-8 JSON имеет вид `{"events": [...]}`. Событие содержит:

| Поле | Правило |
|---|---|
| `id` | Непустая строка, уникальна в файле |
| `timestamp` | ISO 8601 с часовым поясом, точность до целой секунды; `Z` разрешён |
| `service` | Непустая строка |
| `status` | `ok` или `error` |
| `duration_ms`, `bytes` | Неотрицательные целые числа, логические значения не допускаются |
| `route` | Непустая строка, начинающаяся с `/`; query, fragment, Unicode и переводы строк возможны |

Дополнительные поля не участвуют в отчётах. Порядок событий во входе произволен.
Хронологический порядок — время в UTC, затем `id` в лексикографическом порядке.
Обработчик входа уже создаёт поле `at` с `datetime` в UTC для каждой записи.
Внешний интерфейс не требует сохранения этого внутреннего устройства.

Команда `reports` выдаёт JSON-массив имён в порядке `latency`, `reliability`,
`throughput`, `incidents`, `traffic`, `audit`. Команда `check` выдаёт
`{"events":N,"services":S}`. Неверные данные отвергаются с кодом 2,
пустым stdout и непустой строкой в поле `error` JSON-объекта в stderr.

Отчёты пишутся в stdout, успешный код — 0. Все JSON-отчёты — массивы объектов
с точно указанными ниже полями. Пустой вход даёт пустой массив, кроме `audit`.
Входной файл не изменяется. Новые зависимости не нужны.

## latency

Одна строка для каждого сервиса, сортировка по `service`.
Статистика задержек вычисляется только по `status=ok`.

Поля: `service`, `count`, `min_ms`, `max_ms`, `p50_ms`, `p95_ms`, `slow_requests`.
`count` — число успешных запросов; `slow_requests` — число успешных запросов
с задержкой **не менее 1000 мс**. Процентили используют nearest rank:
для отсортированных n значений взять элемент с номером `ceil(p*n/100)`,
нумерация с 1. При отсутствии успешных запросов `count=0`, `slow_requests=0`,
а четыре значения задержки равны `null`. Сервис из одних ошибок не пропускается.

## reliability

Одна строка на сервис, сортировка по `service`. Поля: `service`, `total`, `ok`,
`error`, `availability_bp`, `longest_error_streak`.
`availability_bp = floor(ok*10000/total)` — целое число базисных пунктов.
`longest_error_streak` — наибольшее число подряд идущих ошибок в
хронологической последовательности этого сервиса; успешный запрос обрывает серию.
События других сервисов не обрывают серию.

## throughput

Одна строка на непустую пару (минута UTC, сервис). Поля:
`minute`, `service`, `requests`, `bytes`. Учитывать оба статуса.
Минутные окна полуоткрыты: `[начало минуты, начало следующей минуты)`.
`minute` имеет вид `2026-01-01T00:01:00Z`; пустые окна не создаются.
Сортировка: `minute`, затем `service`. `bytes` — сумма входных значений.

## incidents

Инцидент — непрерывная серия ошибок одного сервиса в хронологическом порядке.
Он начинается с первой ошибки и заканчивается временем следующего успешного
события этого же сервиса. События другого сервиса не влияют на него.
Последняя незакрытая серия также выводится.

Поля: `service`, `start`, `end`, `error_count`, `duration_seconds`.
Время нормализуется в UTC `YYYY-MM-DDTHH:MM:SSZ`.
Для незакрытого инцидента `end=null`, `duration_seconds=null`.
Для закрытого длительность — целое число секунд между `start` и `end`, включая 0.
Сортировка: сервис, время начала, id первой ошибки при одинаковом времени.
Последовательность с одинаковым временем всё равно определяется `id`.

## traffic

Группировать по пути: отбросить query и fragment, то есть всё после первого
`?` или `#`, сохранив остальной текст без декодирования и нормализации.
Учитывать оба статуса. Поля: `route`, `requests`, `bytes`, `services`,
`max_duration_ms`. `services` — отсортированный список уникальных сервисов.
Сортировка строк: `bytes` по убыванию, затем `requests` по убыванию,
затем `route` по возрастанию. Переводы строк в пути допустимы.

## audit

Вывести CSV с заголовком:

```text
id,timestamp_utc,service,status,duration_ms,bytes,route
```

Одна строка на событие, сортировка по времени UTC, затем `id`.
`timestamp_utc` — нормализованное UTC-время с секундами и суффиксом `Z`.
`route` сохраняется целиком, включая query и fragment.
Разделитель — запятая, кавычка — двойная, экранирование — удвоение кавычек,
концы записей — LF (`\n`). Поля с запятой, кавычкой или переводом строки
заключаются в кавычки. Конечный перевод строки обязателен.
Пустой вход возвращает только заголовок с LF.

## report all

Вернуть JSON-объект с ровно шестью ключами из реестра. Значения совпадают с
результатом каждого отдельного отчёта; `audit` в этом объекте — строка CSV.
Результат должен сохраняться при перестановке входных событий и повторном вызове.
